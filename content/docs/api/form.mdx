The Form API lets you programmatically create and manage end-to-end encrypted forms for confidential intake workflows — whistleblowing tip lines, patient intake, legal contact, HR applications, and other workloads where responses must stay private. Submissions are encrypted in the submitter's browser using hybrid public-key crypto and can only be decrypted in your anon.li vault.

## Authentication

The Form API supports two authentication modes depending on the endpoint and use case:

1. **API Key** (recommended for programmatic use) — pass `Authorization: Bearer ak_your_api_key_here`. Generate keys in your [Dashboard](/dashboard/api-keys).
2. **Browser session** — automatic via logged-in session cookie. 2FA must be verified if enabled on the account.

Public form pages at `/f/:id` and the submit endpoint require no authentication (anyone with the link can submit). All creator-side endpoints require a session or API key and count against your monthly Form API quota.

```bash
Authorization: Bearer ak_your_api_key_here
```

https://anon.li/api/v1

## End-to-End Encryption

  <span className="text-blue-800 dark:text-blue-200 text-sm block">
    <strong>Per-form keypair:</strong> Each form has a dedicated P-256 keypair. The public key is served alongside the form schema; the private key is stored AES-GCM encrypted against your vault and never touches our servers in plaintext. Submissions are encrypted in the submitter's browser with ECDH + HKDF + AES-256-GCM; only a vault-unlocked client can decrypt them.
  </span>
</div>

### How It Works

1. **Create keypair** — Generate a P-256 keypair locally. Wrap the private key with your vault key.
2. **Publish** — Send the public key and a vault-wrapped private key when creating the form.
3. **Submit** — Submitters derive a shared secret with the form's public key and encrypt their answers client-side.
4. **Decrypt** — Unlock your vault, unwrap the private key, and decrypt submissions in your dashboard or CLI.

Form metadata (title, description, field schema) is stored in plaintext. An unprotected form serves that schema to anyone with its link; a password-protected form withholds the schema until the visitor supplies a valid password-derived witness. Only submission payloads are end-to-end encrypted.

## Form Schema

Forms are defined by a versioned JSON schema. The schema is self-contained: in addition to the fields, it carries the form's `title` and `description`. Field IDs must be unique within a form, and `displayMode` controls whether questions render all on one page (`classic`) or one at a time (`one_question`).

```json
{
  "version": 1,
  "title": "Whistleblower intake",
  "description": "A discreet intake form. Submissions are encrypted end to end.",
  "displayMode": "classic",
  "fields": [
    { "id": "name", "type": "short_text", "label": "Name", "required": true },
    { "id": "email", "type": "email", "label": "Email" },
    { "id": "report", "type": "long_text", "label": "What happened?", "required": true, "maxLength": 50000 },
    { "id": "urgency", "type": "single_select", "label": "Urgency", "options": ["Low", "Medium", "High"] },
    {
      "id": "phone",
      "type": "phone",
      "label": "Preferred number",
      "visibleWhen": { "fieldId": "urgency", "op": "equals", "value": "High" }
    }
  ],
  "submitButtonText": "Submit report",
  "thankYouMessage": "Thanks. Your report has been encrypted for the intake team.",
  "notifyOnSubmission": true
}
```

The top-level `title` (required, 1–300 chars), `description` (optional, ≤ 2000 chars), and `notifyOnSubmission` (alert the owner on each response) mirror the form's top-level metadata and are kept in sync server-side. They may also be passed separately when creating/updating a form; the stored schema is always reconciled to match.

### Top-level Keys

| Key | Type | Description |
| :--- | :--- | :--- |
| `version` | integer | Always `1` |
| `title` | string | Required, 1–300 chars |
| `description` | string | Optional, ≤ 2000 chars |
| `displayMode` | string | `classic` (default) or `one_question` |
| `fields` | array | ≤ 50 questions; IDs must be unique |
| `submitButtonText` | string | Submit label, default `Submit`, ≤ 60 chars |
| `thankYouMessage` | string | Optional, shown after submission, ≤ 2000 chars |
| `notifyOnSubmission` | boolean | Email the account owner on each submission, default `true` |

### Supported Field Types

Every field shares the common properties `id` (unique, alphanumeric), `label`, `required`, `helpText`, and `visibleWhen`.

| Type | Options |
| :--- | :--- |
| `short_text` | `placeholder`, `maxLength` (≤ 500) |
| `long_text` | `placeholder`, `maxLength` (≤ 50,000) |
| `email` | `placeholder` |
| `number` | `min`, `max`, `step` |
| `phone` | `placeholder` |
| `single_select` | `options[]` (1–50) |
| `multi_select` | `options[]` (1–50) |
| `dropdown` | `options[]` (1–100) |
| `rating` | `max` (3–10, default 5) |
| `date` | `min`, `max` (ISO-8601 `YYYY-MM-DD`) |
| `file` | `maxFiles` (1–20, default 1), `maxFileSize` (bytes), `acceptedMimeTypes[]` |
| `linear_scale` | `min` (0–1, default 1), `max` (2–11, default 5), `minLabel`, `maxLabel` |
| `ranking` | `options[]` (2–20) |
| `address` | `parts` — per-part `{ enabled, required }` for `line1`, `line2`, `city`, `state`, `postalCode`, `country` |

`visibleWhen` gates a question on an earlier field's answer and accepts `fieldId`, `op` (`equals`, `notEquals`, `contains`, `gt`, `lt`, `isEmpty`, `isNotEmpty`), and `value`. Visibility rules must reference an earlier question. An `address` question must collect at least one part. Option lists must be unique, and select/dropdown/ranking options are trimmed and de-duplicated on save.

### Create Form

<div className="flex items-center gap-2 mt-6 mb-4">
    <span className="bg-green-100 dark:bg-green-900/30 text-green-700 dark:text-green-400 px-3 py-1 rounded-md font-mono text-sm font-bold">POST</span>
    <code className="text-sm bg-secondary px-2 py-1 rounded">https://anon.li/api/v1/form</code>
</div>

Creating a form requires a vault-unlocked caller. Clients using API-key authentication must first call `POST /api/v1/vault/unlock` to obtain vault material, then wrap the form's private key locally before sending it here.

**Body parameters**

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `title` | string | Yes | Human-readable title (1–300 chars) |
| `description` | string | No | Shown above the form (≤ 2000 chars) |
| `schema` | object | Yes | `FormSchemaDoc` JSON (see above); its embedded `title`/`description` are reconciled with the top-level fields |
| `publicKey` | string | Yes | Base64url-encoded raw P-256 public key (87 chars) |
| `wrappedPrivateKey` | string | Yes | Vault-wrapped P-256 private key (PKCS#8 inside AES-GCM) |
| `vaultId` | string | Yes | Caller's current vault identity |
| `vaultGeneration` | number | Yes | Caller's current vault generation |
| `allowFileUploads` | boolean | No | Enable file-attachment fields (default `false`) |
| `maxFileSizeOverride` | number \| null | No | Per-upload byte cap override |
| `maxSubmissions` | number \| null | No | Stop accepting submissions after this many |
| `closesAt` | ISO-8601 \| null | No | Close the form at this date |
| `hideBranding` | boolean | No | Remove anon.li branding (Pro only) |
| `notifyOnSubmission` | boolean | No | Email the account owner when a new encrypted submission arrives (default `true`) |
| `customKey` | boolean | No | Password-protect the public form (Plus and Pro) |
| `salt`, `customKeyData`, `customKeyIv`, `customKeyVerifier` | string | No | Required when `customKey: true`; the verifier is a hash of the decrypted password witness |

**Example response**

```json
{
  "data": {
    "id": "aB3x0Yz9Qw8t",
    "title": "Whistleblower intake",
    "public_key": "<base64url>",
    "created_at": "2026-04-22T12:00:00.000Z"
  },
  "meta": { "request_id": "req_..." }
}
```

Returns `402 PAYMENT_REQUIRED` if the caller is over their active-form cap for the current plan.

### Get Form (Public)

<div className="flex items-center gap-2 mt-6 mb-4">
    <span className="bg-blue-100 dark:bg-blue-900/30 text-blue-700 dark:text-blue-400 px-3 py-1 rounded-md font-mono text-sm font-bold">GET</span>
    <code className="text-sm bg-secondary px-2 py-1 rounded">https://anon.li/api/v1/form/:id</code>
</div>

Returns public metadata needed to render the form and encrypt a submission. No authentication required. A disabled or closed form is returned with `active: false`; a taken-down form returns `410 Gone`.

**Response**

```json
{
  "data": {
    "id": "aB3x0Yz9Qw8t",
    "title": "Whistleblower intake",
    "description": null,
    "schema": {
      "version": 1,
      "title": "Whistleblower intake",
      "description": "A discreet intake form.",
      "displayMode": "classic",
      "fields": [ /* ... */ ],
      "notifyOnSubmission": true
    },
    "field_count": 4,
    "public_key": "<base64url>",
    "allowFileUploads": false,
    "hideBranding": false,
    "customKey": false
  },
  "meta": { "request_id": "req_..." }
}
```

For a password-protected form, `schema` is `null`. Decrypt the password witness in the browser, then call `POST /form/:id/unlock` with `{ "customKeyProof": "..." }`. A successful response returns the schema; an invalid witness returns `403`. Never send the raw password.

### Submit (Public)

<div className="flex items-center gap-2 mt-6 mb-4">
    <span className="bg-green-100 dark:bg-green-900/30 text-green-700 dark:text-green-400 px-3 py-1 rounded-md font-mono text-sm font-bold">POST</span>
    <code className="text-sm bg-secondary px-2 py-1 rounded">https://anon.li/api/v1/form/:id/submit</code>
</div>

Posts an encrypted submission. No authentication is required by default. Attachment storage is always billed to the form owner and constrained by the owner's Form attachment entitlement.

**Body parameters**

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `ephemeralPubKey` | string | Yes | Submitter's ephemeral P-256 public key (base64url) |
| `iv` | string | Yes | 12-byte AES-GCM IV (16 base64url chars) |
| `encryptedPayload` | string | Yes | Ciphertext of the JSON answers object (≤ 5 MB) |
| `attachedDropId` | string | No | Paired Drop when the form has file fields |
| `attachmentUploadToken` | string | No | Required with `attachedDropId`; consumed when the submission is recorded |
| `attachmentManifest` | array | No | Required with `attachedDropId`; binds uploaded files to file fields |
| `turnstileToken` | string | No | Required for public submissions when Turnstile is enabled and no attachment upload token was already verified; respondent authentication does not bypass this check |
| `customKeyProof` | string | No | Required when the form is password-protected; this is the decrypted witness, not the password |

Returns `403` if the form is disabled, closed, or taken down, and `402` when the owner is past the calendar-month submission allowance.

### List / Read / Delete Submissions

| Path | Verbs |
| :--- | :--- |
| `/api/v1/form/:id/submission` | `GET` (creator list) |
| `/api/v1/form/submission/:sid` | `GET`, `DELETE` (creator only) |

Submission payloads are returned as ciphertext. Decryption requires ECDH between the caller's vault-unwrapped form private key and the per-submission ephemeral public key, followed by AES-GCM decryption with the stored IV.

## Upload Tokens

<div className="flex items-center gap-2 mt-6 mb-4">
    <span className="bg-green-100 dark:bg-green-900/30 text-green-700 dark:text-green-400 px-3 py-1 rounded-md font-mono text-sm font-bold">POST</span>
    <code className="text-sm bg-secondary px-2 py-1 rounded">https://anon.li/api/v1/form/:id/upload-token</code>
</div>

When a form allows file uploads, this endpoint validates the planned files and mints a form-scoped Drop upload token. Every caller must pass a valid Turnstile token when Turnstile is enabled. Storage is metered against the form owner using the owner's Form attachment limit, and concurrent staging is capped per form.

## Decrypting Submissions

```javascript
// 1. Fetch the wrapped private key from /api/v1/vault/form-keys (vault session required)
const { wrapped } = await fetch('/api/v1/vault/form-keys?formId=' + formId).then(r => r.json())

// 2. Unwrap the P-256 private key using the vault key (AES-GCM payload unwrap)
const privateKey = await unwrapVaultPayload(wrapped, vaultKey)

// 3. For each submission, derive the shared secret and decrypt
const sharedSecret = await crypto.subtle.deriveBits(
  { name: 'ECDH', public: importedSubmitterPubKey },
  privateKey, 256,
)
const aesKey = await hkdfAesGcmKey(sharedSecret)
const plaintext = await crypto.subtle.decrypt(
  { name: 'AES-GCM', iv: ivBytes }, aesKey, ciphertext,
)
// plaintext is the JSON answers object keyed by field id
```

## Security Notes

- **Per-form P-256 keypair** — rotating a key rotates the form and invalidates cached ciphertext.
- **Zero server plaintext** — submission payloads are never available to the server in readable form.
- **Vault-wrapped private keys** — the form's decryption material is stored AES-GCM-encrypted against your vault.
- **Metadata is plaintext at rest** — titles and descriptions are public to link holders. Field schemas are public for ordinary forms and access-gated for password-protected forms. Don't put server-side secrets in form metadata.
