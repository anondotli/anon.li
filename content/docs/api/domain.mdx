---
title: "Domain API"
summary: "Add, verify, and manage custom domains for your email aliases using the Domain API."
---

The Domain API allows you to add custom domains to your anon.li account and verify their DNS configuration. Once verified, you can create aliases using your own domain instead of `@anon.li`.

## Authentication

All API requests must be authenticated using an API Key. Generate keys in your [Dashboard](/dashboard/api-keys).

```bash
Authorization: Bearer ak_your_api_key_here
```

## Base URL

```
https://anon.li/api/v1
```

### Add Domain

Add a new custom domain to your account. A DKIM key pair is generated automatically, so the response already includes `dkim_public_key` and `dkim_selector`. Custom domains require a Plus or Pro plan; adding a domain beyond your plan's limit returns `403`.

<div className="flex items-center gap-2 mt-6 mb-4">
    <span className="bg-green-100 dark:bg-green-900/30 text-green-700 dark:text-green-400 px-3 py-1 rounded-md font-mono text-sm font-bold">POST</span>
    <code className="text-sm bg-secondary px-2 py-1 rounded">https://anon.li/api/v1/domain</code>
</div>

**Body Parameters**

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `domain` | string | Yes | Domain name in lowercase (e.g., `mail.example.com`). Must match `^[a-z0-9.-]+\.[a-z]{2,}$`. |

**Example Request**

```bash
curl -X POST https://anon.li/api/v1/domain \
  -H "Authorization: Bearer ak_..." \
  -H "Content-Type: application/json" \
  -d '{"domain": "mail.example.com"}'
```

**Response (201)**

```json
{
  "data": {
    "id": "domain_xyz123",
    "domain": "mail.example.com",
    "verified": false,
    "ownership_verified": false,
    "mx_verified": false,
```

### Get Domain Details

**Example Request**

```bash
curl https://anon.li/api/v1/domain/domain_xyz123 \
```

### Verify Domain

Check DNS records and update the domain's verification status. A domain is `verified` only when the ownership TXT, MX, SPF, **and DKIM** records all resolve correctly. `dns_verified` reports whether the mail-routing records (MX, SPF, DKIM) are correct, independent of ownership.

<div className="flex items-center gap-2 mt-6 mb-4">
    <span className="bg-green-100 dark:bg-green-900/30 text-green-700 dark:text-green-400 px-3 py-1 rounded-md font-mono text-sm font-bold">POST</span>
    <code className="text-sm bg-secondary px-2 py-1 rounded">https://anon.li/api/v1/domain/:id/verify</code>
</div>

**Example Request**

```bash
curl -X POST https://anon.li/api/v1/domain/domain_xyz123/verify \
  -H "Authorization: Bearer ak_..." \
  -H "Content-Type: application/json" \
  -d '{}'
```

**Response**

```json
{
  "data": {
    "verified": true,
    "ownership_verified": true,
    "mx_verified": true,
    "spf_verified": true,
    "dkim_verified": true,
    "dns_verified": true
  },
  "meta": {
    "request_id": "req_abc123"
  }
}
```

### Regenerate DKIM Key

Generate a new DKIM key pair for a domain and return the new DKIM DNS record.

<div className="flex items-center gap-2 mt-6 mb-4">
    <span className="bg-green-100 dark:bg-green-900/30 text-green-700 dark:text-green-400 px-3 py-1 rounded-md font-mono text-sm font-bold">POST</span>
    <code className="text-sm bg-secondary px-2 py-1 rounded">https://anon.li/api/v1/domain/:id/dkim</code>
</div>

<Callout type="warning" title="This replaces your existing DKIM key">
Regenerating invalidates the DKIM TXT record currently published in your DNS and resets `dkim_verified` to `false`. Because DKIM is required for verification, the domain will not pass verification again until you publish the new record and call the verify endpoint. To read the current DKIM record without rotating it, use `GET /api/v1/domain/:id` (`dns_records.dkim`).
</Callout>

**Example Request**

```bash
curl -X POST https://anon.li/api/v1/domain/domain_xyz123/dkim \
  -H "Authorization: Bearer ak_..."
```

**Response**

```json
{
  "data": {
    "id": "domain_xyz123",
    "domain": "mail.example.com",
    "dkim_selector": "default",
    "dkim_record": {
      "type": "TXT",
      "host": "default._domainkey.mail.example.com",
      "value": "v=DKIM1; k=rsa; p=MIIBIjANBgkq..."
    }
  },
  "meta": {
    "request_id": "req_abc123"
  }
}
```

## Domain Object

| Field | Type | Description |
| :--- | :--- | :--- |
| `id` | string | Unique domain identifier |
| `domain` | string | The domain name |
| `verified` | boolean | Ownership, MX, SPF, and DKIM records all verified |
| `ownership_verified` | boolean | TXT ownership record verified |
| `mx_verified` | boolean | MX record verified |
| `spf_verified` | boolean | SPF record verified |
| `dkim_verified` | boolean | DKIM record verified |
| `verification_token` | string | Token for ownership TXT record |
| `dkim_public_key` | string \| null | DKIM public key (PEM). Generated automatically when the domain is added |
| `dkim_selector` | string \| null | DKIM selector (`default`) |
| `created_at` | string | ISO 8601 creation timestamp |

---

## Verification Workflow

1. **Add your domain** - `POST /api/v1/domain`
2. **Get DNS records** - `GET /api/v1/domain/:id` to see the required ownership TXT, MX, SPF, and DKIM records in `dns_records`
3. **Configure DNS** - Add all four records to your DNS provider. DKIM is required: a domain without a valid DKIM record does not verify
4. **Verify** - `POST /api/v1/domain/:id/verify` to check your configuration

Only call `POST /api/v1/domain/:id/dkim` if you need to rotate the DKIM key; it replaces the published key and you must update DNS and verify again.

## Error Responses

| Status | Code | Description |
| :--- | :--- | :--- |
| `400` | `VALIDATION_ERROR` | Invalid domain format, or a reserved domain (`anon.li` and its subdomains) |
| `401` | `UNAUTHORIZED` | Invalid or missing API key |
| `402` | `PAYMENT_REQUIRED` | Team workspace without an active Business plan |
| `403` | `FORBIDDEN` | Custom domains not included in your plan, or domain limit reached |
| `404` | `NOT_FOUND` | Domain not found |
| `409` | `CONFLICT` | Domain already added to your account, or already verified by another account |
| `429` | `RATE_LIMITED` | Too many requests |
